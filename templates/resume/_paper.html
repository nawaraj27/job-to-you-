{% comment %} The document itself. Rendered from the same flattened `Document` the PDF and DOCX renderers consume and sized by the same theme, so what a candidate arranges on screen is what downloads. One partial, used by the editor's preview, the print view and the template gallery, so the three can never drift apart. Blocks arrive already grouped into head / band / body / sidebar. The template does not decide which section goes where — that is `rendering/theme.py`, which the exporters read too. {% endcomment %} {% comment %} The theme's numbers go on `.sheet-inner`, not on `.sheet`. Every one of them is a multiple of `--sheet-unit`, and a custom property whose value references another custom property is resolved on the element where it is *declared* — not lazily at each descendant that reads it. Declared on `.sheet`, where `--sheet-unit` does not exist, all of them computed to the guaranteed-invalid value and silently inherited as nothing: the sidebar grid collapsed to one column and every type size fell back to whatever it inherited. `.sheet-inner` is where the unit lives, so it is where the rest must live too. {% endcomment %}
